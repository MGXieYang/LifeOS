# LifeOS 产品范围 V3.0

本文件是当前唯一有效产品事实源。V1、V2、Decision、FreeTime 和旧天平需求只可用于历史追溯，不得覆盖本文件。

LifeOS 只聚焦工作与收入、消费与价值、人生时间。底部导航固定为当下、天平、时间、设置。

- 当下：首页只以今日牛马状态、本月已赚、距离发薪为核心；系统时钟驱动实时计算，不保存累计金额。
- 天平：输入金额与可选名称，展示工作小时、工作日、月薪比例和集中策略得出的压力等级；可选计算长期使用价值，保存历史不是必需步骤。
- 时间：展示年度进度与余额、人生时间轴、自定义节点、渐进式退休结果和未来 90/180/365 天时间预算。
- 设置：工作、个人、显示、数据、关于。默认 09:30—19:00，午休 12:30—14:00，有效工作 8 小时，发薪日 7 号；出生日期和退休类别可跳过。需求文档 V3.0 正文中的 19:30 与 8.5 小时是已由产品方纠正的笔误，以本条为准。

核心计算完全本地、离线运行，不依赖登录、后端、云服务、网络 API、后台计时服务或第三方分析。法定工作日使用本地 Calendar 文件；缺失年度按普通星期规则估算并明确提示。

明确不开发 Decision、FreeTime、Todo、日记、睡眠、健康、运动、通勤、习惯、复杂资产、AI 聊天、工作任务和日历管理。

实施顺序为 Gap Analysis → Phase 1 当下与设置 → Phase 2 基础天平 → Phase 3 长期价值与历史 → Phase 4 时间 → Phase 5 未来时间预算。Phase 6 视觉与数据备份不在本轮范围。

## 首次启动与设置

首次启动先显示 LifeOS 与“看见你的时间，也看见它值多少钱”，再采集税后月工资、上班/下班、午休开关与时段、发薪日。出生日期和退休类别必须同时填写或一起跳过。设置页允许随时修改同一信息。界面动画固定启用，不提供动画或轻松/简洁模式开关；主题保留跟随系统/浅色/深色，点击主题后立即应用并保存。

## 当下验收

今日卡必须覆盖上班前、工作中、午休、下班后、非工作日。午休和非工作日收入停止；下班后收入封顶。用户进入后应直接看到今日收入、已工作时间、倒计时与今日进度。本月卡展示当前收入、月工资、进度、已完成/总工作日；未来工作日不得提前计入。发薪卡展示目标日期以及剩余天、小时，发薪日当天全天显示“今天发工资”。

## 天平验收

用户输入金额后立即看到五级压力结论、工作小时、工作日、月工资比例，以及随金额变化的天平和砝码；Slider 可连续比较不同价格。商品名可空，App 不输出推荐买/不推荐买。长期价值默认关闭，开启后采集使用月数与每天/每周/每月频率，输出预计次数和单次/每天/每月成本。用户可以只算不保存；提供重置当前称量按钮，重置不影响历史。历史通过独立页面展示，记录不会自动清除，只能由用户逐条手动删除。

## 时间验收

进入时间页立即看到年度进度、剩余自然日/工作日/非工作日/法定假期。填写个人信息后显示当前年龄、未来 40/50 岁节点、退休位置和退休倒计时。自定义节点支持年龄与日期，只计算时间距离，不包含 Todo 状态。时间首页只展示节点列表，未来预算固定提供 90/180/365 天，显示工作日、非工作日、显式法定假日和完整可休周末；Calendar 缺失必须提示估算。

## 数据与技术约束

DataStore 只保存工作、个人、显示和 Onboarding 设置；Room 保存 BalanceHistory 与 LifeNode。删除旧字段和旧表必须使用迁移，禁止通过清空用户数据升级。WorkCalendar、WorkTimeCalculator、SalaryCalculator、RetirementCalculator 的已验证正确算法优先保留。天平阈值集中在 PurchaseWeightPolicy；长期价值和未来预算分别由独立 Calculator 实现并有确定性 JVM 单测。
