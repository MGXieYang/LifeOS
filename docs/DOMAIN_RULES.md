# LifeOS V3.0 业务规则

## 工作日

年度 Calendar 中 WORKDAY/HOLIDAY 优先；未覆盖日期按周一至周五工作、周六周日休息。当前年份未收录完整官方 Calendar 时必须显示估算提示。周末补班属于工作日。

## 工时与状态

默认上班 09:30、午休 12:30—14:00、下班 19:00，有效 8 小时。产品方已明确 V3.0 DOCX 中 19:30/8.5 小时是笔误。启用午休时必须满足上班 < 午休开始 < 午休结束 < 下班；关闭午休时按完整上下班时段计薪。暂不支持跨夜。

状态只有 BEFORE_WORK、WORKING、LUNCH_BREAK、AFTER_WORK、HOLIDAY，边界左闭右开。非工作日工时为零。工作分段截断到各自合法范围。

## 收入与倒计时

当月总秒数 = 当月工作日数 × 每日有效秒数；秒薪 = 税后月薪 / 当月总秒数。今日收入和本月收入始终用月薪乘累计有效秒数后一次除法，禁止累计舍入日薪；完整月末必须精确等于月薪。UI 金额 HALF_UP 保留两位。

上班前倒计时至上班；午休倒计时至午休结束；工作中倒计时至下班；其他状态为零。发薪日使用配置日与月末较小值，当天全天显示今天发工资，次日起指向下月。

## 天平

工作代价只由金额、当月税后工资、每日有效工时、当月有效工时换算：工作小时、工作日、月工资比例。0 元合法，负数非法。

PurchaseWeightPolicy 集中定义压力等级：不高于 10% 月薪且不超过约 2.2 工作日为 LIGHT；不高于 25% 为 SLIGHTLY_LIGHT；不高于 50% 为 NORMAL；不高于 100% 为 HEAVY；更高为 VERY_HEAVY。UI 不得复制阈值，不输出购买建议。

UsageValueCalculator 要求价格非负、使用月数和频率大于零。按 365 天/年、52 周/年、12 月/年估算使用次数，并输出单次、每天、每月成本。长期总结只使用规则系统。

## 人生时间

年度剩余从明天起算到当年末；法定假期只统计 Calendar 明确标记的 HOLIDAY 日期。当前年龄用出生日期到系统日期的 Period。年龄节点由出生日期加目标年龄得到，日期节点使用目标日期；已到达节点剩余为零。自然周末指目标前完整出现的星期六+星期日，不等同于法定非工作日。

退休规则见 `RETIREMENT.md`，必须由 RetirementCalculator + RetirementPolicy 计算；未来工作日始终标记估算。

## 未来时间预算

90/180/365 天窗口均从明天开始并包含第 N 天，共计 N 个自然日。工作日按 Calendar，非工作日为窗口总天数减工作日；法定假期为显式 HOLIDAY；完整可休周末要求同一窗口内连续的星期六和星期日都不是法定工作日。窗口包含缺失 Calendar 的年份时必须标记估算。

## 时间事实来源

系统时钟是当前时刻唯一事实来源。250ms 刷新只负责触发 UI；关闭、后台、锁屏、被杀或重启后均重新按系统时间计算，不使用后台服务，不保存累计金额。

## 删除范围

Decision、DecisionReview、DecisionStatistics、FreeTime、睡眠、通勤、必要生活时间和自由夜晚换算均不属于 V3 Domain。

## Phase 同步

- Phase 1：确认 19:00 默认、五态工作状态、系统 Clock、月收入与发薪规则；删除 Decision/FreeTime。
- Phase 2：落地工作代价与 PurchaseWeightPolicy。
- Phase 3：落地 UsageValueCalculator 的周期与频率口径。
- Phase 4：落地年度、年龄、节点、自然周末和退休口径。
- Phase 5：落地未来窗口、显式法定假日和完整可休周末口径。
